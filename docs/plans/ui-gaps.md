# Plan: context menus and the remaining UI gaps

Status: implemented on branch `integrate` (2026-10-13); see "Outcome" at the end. Source of truth for behaviour: upstream TortoiseGit
(see `docs/spec/`). Every phase ends with `cargo fmt --check`,
`cargo clippy --all-targets -- -D warnings` and `cargo test`.

## Where we are

- Context menus exist in three places only: Log commit rows (`ui/log.slint`),
  RefLog rows and Browse References rows (`ui/refbrowse.slint`). They are
  hard-coded `ContextMenuArea { Menu { ... } }` blocks with fixed integer ids
  (`src/log.rs` `mod action`). They ignore upstream's per-entry conditions
  (merge commit, HEAD, working-tree row, selection count, refs present, ...).
- The shared file list (`ui/common.slint` `FileList`) declares a `context(int)`
  callback that nothing uses. Commit, Add, Revert, Resolve, Working Tree and the
  Log's changed-files pane therefore have no right-click menu at all.
- No list supports multi-selection, so every upstream entry that needs two or
  more selected rows (compare revisions, revert several commits, cherry-pick
  selected, ...) cannot exist yet.
- Post-command buttons (`progress::PostAction`) can only launch another
  `/command:`. In-process follow-ups such as Merge's "Remove branch" can't be
  expressed.
- Missing commands and dialogs: export, formatpatch, importpatch, sendmail,
  svn*, newworktree/worktreelist/dropnewworktree, repobrowser, revisiongraph,
  requestpull, subadd, firststart, dropmove/dropcopyadd, daemon, pgpfp,
  commitisonrefs, updatecheck, and the File Diff dialog (upstream's file-list
  window for comparing two revisions).

## Design decision: data-driven menus

Menu *content* is decided in Rust by pure functions that mirror upstream's
conditions. Slint only renders what it is given. This keeps behaviour testable
without a GUI. Menus are native popups, so the snapshot hook can't capture them;
unit tests on the builders replace screenshots.

```text
koopagit-dialogs/src/menus/
  mod.rs        MenuEntry tree, lazy separators, Slint conversion, ActionId
  filelist.rs   GitStatusListCtrl menu  (spec §3.4)
  log.rs        GitLogListBase menu     (spec §2.2.2) + message-pane menu
  refs.rs       RefLog / Browse References
  ...           one file per menu family
```

```rust
pub struct MenuEntry { pub id: ActionId, pub title: String, pub enabled: bool,
                       pub checked: Option<bool>, pub children: Vec<MenuEntry>,
                       pub separator: bool }
// e.g.
pub fn file_list_menu(sel: &[&Item], mask: PopMask, state: &RepoState) -> Vec<MenuEntry>;
```

Slint side (one reusable pattern in `ui/common.slint`):

```slint
export struct MenuLeaf  { id: int, title: string, enabled: bool }
export struct MenuEntry { id: int, title: string, enabled: bool, separator: bool,
                          children: [MenuLeaf] }   // two levels covers every upstream menu
// in a list row:
ContextMenuArea {
    Menu {
        for e in root.menu-for(i): ...   // pure callback, evaluated when the menu opens
    }
}
```

`ActionId` is a Rust enum with an explicit `i32` mapping. Slint reports
`(row, id)` back and the dialog's controller dispatches on it.

## Phase 0.1 spike result (2026-10-13)

- `for x in model: if cond: Element` is not valid Slint, so one flat model can't
  mix items, separators and submenus. A `for` may only repeat one element type.
- Components may inherit `ContextMenuArea` and declare the `Menu` themselves, so a
  reusable menu component works.
- On macOS `ContextMenuArea` shows a **native** `NSMenu`; `show(point)` opens it
  programmatically and runs a modal loop. Native menus never appear in
  `KOOPAGIT_SNAPSHOT` images.
- Each `show` instantiates the menu item tree, so a `pure callback` used in the
  menu is evaluated at open time with the current state (observed: called with
  the row set just before opening).

**Decision:** `ui/dynmenu.slint` defines `DynMenuArea inherits ContextMenuArea`
with a fixed number of *blocks*. Each block repeats `MenuItem`s, then `Menu`
submenus, then an optional `MenuSeparator`. Rust (`menus::pack`) splits a flat
entry list into blocks; the dialog answers `menu-for(row)` from a per-open cache.
The `.slint` file is generated by `menus::slint_template()` and a test keeps them
in sync.

## Phase 2: file-list context menu (largest reuse; one builder, six dialogs)

Builder `menus/filelist.rs`; wired into `FileList` and so into Commit, Add,
Revert, Resolve, Working Tree (`repostatus`) and the Log changed-files pane.
Per-dialog masks follow spec §3.4 (for example, Commit hides "Commit…", Resolve
hides Ignore/Add/Commit/Export/Restore).

| Group (upstream order) | Entries | Action |
|---|---|---|
| Conflicts | Edit conflicts · Resolved · Resolve conflict using "mine" / "theirs" | `/command:conflicteditor`; `/command:resolve /noquestion /silent`; `core::fileops` resolve-mine/theirs |
| Unversioned | Add · Add as Executable (+x) · Add as Symlink · Commit… | `git add -f`; `git update-index --add --chmod=+x`; `--cacheinfo 120000,...`; `/command:commit` |
| Compare | Compare with base / Three way diff · Show changes as unified diff · Compare with working tree · Compare parent with working tree · (2 selected) Compare revisions, Compare two files | `/command:diff` / `showcompare` with `/startrev /endrev /unified`; `/path /path2` |
| Change | Commit… · Revert… · Revert to this revision · Revert to parent revision | `/command:commit|revert`; `git checkout <rev> -- <p>` |
| Flags | Skip worktree · Assume unchanged · Unflag both | `git update-index --[no-]skip-worktree`, `--[no-]assume-unchanged` |
| Commit only | Restore after commit / Restore | copy to temp, restore after commit (the existing "Restore after commit" prompt) |
| History | Show log · Show log of submodule · Show log before rename/copy · Blame | `/command:log /path`, `/command:blame` |
| Files | Export selection to… · Save revision to… · View in alternative editor · Open · Open with… · Explore to | `git show <rev>:<p> > dest`; OS open (`open`, `xdg-open`, `explorer`) |
| Compare later | Mark for comparison · Compare with "<marked>" | same `DiffLater` setting as the shell |
| Destructive | Delete · Ignore ▸ (by name / `*.ext`) | `git rm` or filesystem delete after confirmation; `core::fileops` ignore |
| Copy ▸ | full paths · relative paths · file/folder names · all information · per column | `clipboard.rs` |
| LFS | Lock · Unlock | `git lfs lock|unlock` |

After any action that changes the index or working tree, the list refreshes
(F5 path). Not planned: changelists (upstream "ignore-on-commit"), record as a
divergence.

Done when: builder tests cover each dialog mask × entry state (unversioned,
modified, added, deleted, renamed, conflicted, submodule) × 1/2/n selected,
and the Commit dialog actions are exercised in a scratch repo.

## Phase 3: Log dialog menus, complete

Replace the static block in `ui/log.slint` with `menus/log.rs` (spec §2.2.2).

- **Single selection, conditional**: working-tree pseudo-row (Compare with working tree, Commit…, Abort Merge, Stash changes/Pop/List, Pull, Fetch, Submodule Update, Clean up); Blame previous revision (parent submenu for merges); unified diff / Compare with previous (parent submenus for merges); Bisect good/bad/skip/reset when bisecting; Merge to / Reset / Switch / Create Branch / Create Tag / Rebase onto; Export this version; Revert change (parent submenu); Edit Notes; Push "<ref>"; Pull (on HEAD); Delete branch/tag ▸ (with All); Collapse/Expand.
- **Two or more selected**: Compare revisions; unified diff A..B; Show log of A..B / B..A / A...B; Compare change sets; Revert changes by these commits; Bisect start (2 selected); Combine to one commit (contiguous range ending at HEAD: `git reset --soft <oldest>^` + commit with concatenated messages); Cherry Pick selected commits; Format Patch.
- **Always**: Copy to clipboard ▸ (all 9 variants); Search log messages…; Show branches this commit is on.
- **Message pane menu**: Copy, Copy all information, Edit Notes.
- **Ref label (top-left) menu**: Browse References, HEAD -> "<branch>", FETCH_HEAD, All, All basic refs, All local branches, ref history.

Prerequisites: 0.3 (multi-select), the working-tree pseudo-row (spec §2.2,
`LogIncludeWorkingTreeChanges`), and from Phase 5 the File Diff dialog,
Export, Format Patch and the Rebase cherry-pick mode. Until those exist the
entries are shown disabled, not hidden, so the menu order already matches
upstream.

## Phase 5: dialogs that menu entries need

Ordered by how many menu entries each one unblocks:

1. **File Diff dialog** (`CFileDiffDlg`): list of changed files between two revisions (Compare revisions, Compare change sets, `showcompare` on folders). Reuses `FileList` + Phase 2 menu.
2. **Rebase cherry-pick mode**: same dialog, title "Cherry Pick", `-x` option (`CherrypickAddCherryPickedFrom`). Plus the missing rebase features (Onto, Edit stops, squash message concatenation, Continue after conflict).
3. **Export** (`/command:export [/rev]`): `git archive --format=zip -o <file> <rev>`.
4. **Format Patch** (`/command:formatpatch`) and **Apply Patch Serial** (`/command:importpatch`): `git format-patch`, `git am`.
5. **Edit Notes**: input box, `git notes add -f -F <tmp> <sha>`.
6. **Worktrees** (`newworktree`, `worktreelist`, `dropnewworktree`), **Submodule Add** (`subadd`), **Request pull** (`requestpull`: `git request-pull`).
7. **Repo browser** (`repobrowser`: tree from `git ls-tree` at a revision, with its own menu).
8. Lower priority: Revision graph, Send Mail, git-svn commands, daemon, pgpfp, commitisonrefs, firststart, updatecheck, drag-and-drop commands.

## Verification

- Menu builders: unit tests per menu for entry order, visibility and enabled state across selection and repo states. These are the primary test for menus because native popups don't appear in `KOOPAGIT_SNAPSHOT` images.
- Actions: core-level tests that run each new git command line in a scratch repo.
- Interaction: evaluate `i-slint-backend-testing` to drive clicks and menu activation in tests. Fall back to calling the generated `invoke_menu_action(row, id)` directly.
- Manual: a click-through checklist per dialog (right-click each row type, run each entry) to go through together, since GUI interaction can't be automated here.
- Every intentional difference goes into `docs/divergences.md`.

## Decisions (settled 2026-10-13)

1. **New dependencies: yes.** `arboard` (clipboard), `rfd` (native file/folder pickers), `trash` (recycle bin for Revert/Clean).
2. **Phase 5 item 8: in scope.** git-svn commands, Send Mail and the Revision graph are included (after items 1-7).
3. **Upstream quirks:** keep copying them, as before; each one stays listed in `docs/spec/` §3.5 or `docs/divergences.md`.

## Outcome (2026-10-13)

Phases 0-6 were implemented by five parallel workers (A-E) plus a wiring pass and
merged on `integrate`: fmt, clippy `-D warnings` and 186 tests pass; 39 launcher
commands render through `KOOPAGIT_SNAPSHOT` without errors. Native context menus
are verified by builder unit tests only; no interactive click-through yet.

Known issues and leftovers (details in `docs/divergences.md`):
- Log: no Collapse/Expand; Shift-held menu variants and per-ref-label hover
  targeting are impossible with Slint's `ContextMenuArea`.
- Reflog menu lacks Switch/Push/Delete <ref>/Search/Collapse and parent submenus.
- Rebase: no Add button or Revision Files tab; replay runs on the UI thread.
- Diff/merge viewer menus lack header-bar and whitespace/EOL/encoding entries;
  blame viewer has no log pane.
- Commit editor menu lacks spelling, undo/redo and split lines.
- Colors/fonts settings are stored but not applied; Credential, Issue Tracker
  Integration and Icon Set pages are still stubs.
- `autotexttest` and Windows 11 menu registration are not implemented.
